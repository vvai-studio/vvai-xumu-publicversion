# 输入与旁白

## 视频

- 先读当前 Video Use 的 SKILL.md，再用它转录和剪辑；helper 参数以 `--help` 和实现为准。
- 探测分辨率、时长、帧率、声道与旋转。混合帧率先定交付帧率；竖屏交付重新构图。
- 保留逐字 ASR（含停顿、语气词、重录信号）。有缓存且源文件未变就复用；云端转录先给用户看引擎与费用，同意后才上传（见 [后端发现](backends.md#各后端)）。
- 记录素材路径、片段实例 ID、原片起止与剪后起点。剪点对齐词边界，留合理边缘，加短音频淡入淡出。
- 原片可作全片背景，B-roll 与动画只覆盖需要的时段。主剪辑锁定后生成字幕和 `visual-plan.json`。

## 音频

- 确认原声保留范围或用户允许的剪辑策略，保住语气、节奏与人物意图。
- 转录、选段、短淡入淡出后生成旁白母带，复核新时间戳。
- 先确认 Video Use helper 是否支持纯音频；不支持时用 FFmpeg 提取拼接，并保存片段映射。
- 画面覆盖全片：连续插画、录屏、图解、设计背景加文字都可以，一句话不必对应一个镜头。数字人只在用户要求、或决策书建议并经用户确认时加入：一张照片 + 定稿文案生成人物视频，见 [数字人](avatar.md)。
- 母带是唯一主旁白；B-roll 与生成片段的自带人声静音。

## 文案

先判断它是"待改写脚本"还是"已有录音的逐字稿"。默认保留观点、事实与顺序；改写句子或扩写故事需用户授权，屏幕短文案另存。

- **原声**：先做结构与粗分镜，用户录音后再对齐。只有逐字稿时，时间戳标为估算。
- **合成旁白**：用 `audio_cloud.py`（配置与付费规则见 [声音后端](backends.md#声音后端)）。
  1. 文案写成 `## 段落编号` 分段的 Markdown（或 JSON）。原文一字不改，只加标点和停顿标记 `<#0.5#>`；专有名词、英文缩写、数字的读法写进读音表（用户级在配置的 `audio.voice.pronounce`，项目级在 `<edit>/pronounce.json`），只改送给接口的文字，字幕与时间表保留原文。
  2. 音色：用户说了名字就用那个；没说时用默认音色，或只有一个时直接用；名字找不到时列出已登记的音色，不猜。没有登记任何音色时，按声音后端的 [选音色](backends.md#声音后端) 顺序：账号声纹库 → 平台自带音色（试听后登记）→ 自己录音或无旁白。
  3. `voice estimate` 报价 → 先生成约 20 秒试听样（`voice speak --section <段>`）给用户听 → 确认后 `voice speak` 生成全片，得到 `tts/narration.wav`（造物社会把短段合并成至少 200 字一次合成再切回，省掉每次的最低收费）。质量用 hd，pitch 不改，整片情绪统一；语速在生成时调，不用 atempo 事后变速。
  4. `voice align` 把每个字的时间套回原文，输出 `cue_chars.json`、`sections.json` 与 `tts/align_report.md`。转录听错的同音字、绕口令这类转录跟不上的段落已按原文和韵母能量峰定位；报告里的疑点逐条试听，读错的只重新生成那一段（`--section`），其余段落复用缓存。
  5. 声音确认后记 `narration.kind=tts`、锁定旁白，之后的 `cue.py sync` 与镜头制作和原声流程相同。
- **无旁白**：字幕或音乐驱动，按阅读与动作时长排帧，记 `narration.kind=none`。

按估算语速得出的时长标为草案。`--ready` 前，实际音轨与帧级计划一致，字幕时间来自音轨对齐。

## 时间线修订

1. 源文件与转录缓存分开保存；旁白文件变化即触发时间线复核。
2. 同一片段重复使用时分配不同实例 ID。简单硬切用差值映射；变速、重叠转场、跨段动效显式重新映射。
3. 增删、变速、重排后递增 `timeline.revision`，重算受影响的镜头、字幕与 SFX。可复用的独立动画重新核对新窗口的长度与语义同步后再标状态。
4. 改色、局部改字等不动时间线的修改，只更新相应资产与验收记录。

## 最少启动问题

从已知信息补全，只问会实质改变结果的缺项：输入模式、[制作定位](production-profile.md) 各项、必须保留的内容、声音选择、外部生成预算与上传许可。定位不替代剪辑或配音授权；外部模型暂缺时，继续推进规划与代码镜头。
