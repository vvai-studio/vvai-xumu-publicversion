# 本地看板：只看和选

对话框里用文字描述画面、风格、镜头状态效率很低，看板把这些放到一个本地网页上；驱动权仍在对话框，看板不是第二个对话框。

```text
python <skill>/scripts/board.py serve --workspace <工作区> [--edit <edit>] [--port 8765] [--media <媒体目录>]
```

标准库起服务，单个 HTML 加内联脚本，没有构建步骤，只监听 127.0.0.1。Claude 桌面版里用内置浏览器窗格打开它（`preview_start` 给这个地址），其他客户端把地址打印给用户自己点。进入创作板块（流程 0）时顺手起一次；用户说"不用看板"就不起。

## 五个页

| 页 | 看什么 | 来源 |
|---|---|---|
| 创作决策书 | 当前模式、归属格、编剧页五格、导演页四格、理由记录；第 6 格的方向带代表帧 | `<edit>/director.json` |
| 频道档案 | 品牌层、每个栏目、最近改动 | `<工作区>/channel/` |
| 素材 | 剪素材链的缩略图墙 | `<edit>/footage/scan.html` |
| 风格画廊 | 126 种风格的代表帧、色板、模板 / 参考片标记、开源风格包的在线样片链接，按大类分组 | `library/styles/*/style.json` + `assets/gallery/` + 媒体目录 |
| 镜头与确认点 | 五个确认点按模式的必过与状态；visual-plan 的镜头、状态、静帧；最近一次风格合规检查 | `director.json`、`visual-plan.json`、`verify/` |

看板只读文件，文件变了刷新页面即可。

## 三种写操作（仅此三种）

| 按钮 | 转调 | 结果 |
|---|---|---|
| 决策书第 6 格 / 画廊里的"选这个" | `director.py update --from {grids.6.style_choice}` + `confirm --grids 6` | 主风格定下，第 6 格标已确认 |
| 每一格的"确认这一格" | `director.py confirm --grids <n>` | 该格标已确认；全部确认后决策书记 `confirmed_at` |
| 确认点的"通过 / 跳过" | `director.py gate pass|skip <名> [--note]` | 记进决策书与 project.md 的确认点行；跳过必须写理由 |

每一次写都走 `director.py` 的命令行，和总控手工操作同一条路，`director.json` 仍是唯一事实源。不做自由文本编辑：改一句话、改故事线、换栏目，仍在对话框里说，总控用 `update` / `change` 改。

## 边界

- 没有 `director.json` 的项目只能看频道与画廊，写操作返回"没有打开的项目"。
- 静态文件只从媒体目录、Skill 目录、edit 目录三个根下读，跳出根的路径一律 404。
- 看板不替代确认：用户在看板上点了确认，总控下一步照常读 `director.json`；用户在对话框里说的确认，总控用命令记，看板刷新后一致。
- 端口被占用就换 `--port`；服务随会话结束而停，重新进入项目再起。
