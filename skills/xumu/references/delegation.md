# 分工与派活

总控一个人能做完整条片子。派活只为两件事：几个互不相干的镜头同时做，省时间；让一双没参与制作的眼睛来验收，少漏问题。代价是 token：每个子 agent 都要重读身份文件、规范和派活单。所以按片子大小决定，不默认全开。

宿主不支持子 agent 时，本文件的活全部由总控按对应身份文件自己做；独立终检做不了，按 [独立审查](qa.md#独立审查) 记"未做独立审查"。

## 1. 什么时候派

| 情况 | 镜头制作员 | 质检员：截帧核对 | 质检员：独立终检 |
|---|---|---|---|
| 素剪 `plain`、轻包装 `light` | 不派 | 不派 | 不派 |
| 精做 `full`，参考片过门后待做的动态镜头不到 4 个 | 不派 | 不派 | 派 |
| 精做 `full`，待做的动态镜头 4 个及以上 | 派，同时最多 3 个 | 截帧时刻超过 40 张时派 | 派 |

- **参考片由总控自己做**。设计规范、卡片外壳和每种镜头类型的第一个样子都在参考片里定下来；过了 [参考片门](qa.md#参考片门) 才有东西可以交给别人照着做。过门之前不派镜头制作员，也不派截帧核对。
- 数字人按 [AI 视频制作员](../agents/ai-video.md) 自己的规则派，不看这张表。
- 用户说"省着用"或"不要子 agent"时都不派；用户点名要并行或要独立审查时按用户的来。
- 表里的 4 个、3 个、40 张是起步值，还没有实测依据。每个项目按第 4 节记录，攒几条片子之后再调。

## 2. 用哪一档模型

宿主能给子 agent 选模型时：

| 活 | 模型 |
|---|---|
| 独立终检；纯定制镜头 | 与总控同档 |
| 照 demo 改的镜头；截帧核对；数字人 | 可以低一档 |

看图下判断的活不用最小的那一档。宿主不能选模型时用它的默认。

**机械的活不派 agent**：环境自检、下载样片、剪点窗口核对、交付规格检查都是脚本，放后台运行就行，不用为它起一个子 agent。

## 3. 派活的规矩

- **一份派活单一件事**。子 agent 看不到对话，只知道派活单里写的：路径写全；规范给文件路径，不给转述；写明能写哪些文件、做到什么算完、交回什么。
- **两个子 agent 不写同一个文件**。镜头制作员只写自己镜头的源文件和 `shots/<id>/`；质检员只写 `verify/qc/`。
- **不派出去的**：和用户说话、任何确认点、创作决策书、`visual-plan.json` 与时间线、整片与短测渲染、付费调用（数字人按它自己的额度规则）、发布。
- **交回的是报告，不是证据**（原则 5）：
  - 镜头制作员交回后，总控自己看每个镜头的入场、峰值、落定截帧，再把几个镜头的短测合成一次渲染；`refs_viewed`、`short_test` 仍由总控记。
  - 质检员报的问题，总控对照图确认属实再改，不照单全收；报"没问题"的，每种镜头类型至少抽看一张。
- **退回两次还不行就收回**：同一份活退回两次仍不合格，总控自己做，记一句原因，不再换人重派。

## 4. 记录

`project.md` 里记一行：哪些镜头派出去了、各用哪一档模型、退回几次、收回几个；终检报了几条、其中几条属实。这些数用来调第 1 节的起步值，也让用户知道这条片子多花在了哪里。
